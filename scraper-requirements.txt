Act as a Senior Python Scraping Engineer. Build a scalable, modular, and production-ready web scraping pipeline using Scrapy for my Zodiac Character Matcher website.

## 1. Project Objective

I am building a website that matches users with fictional characters based on zodiac signs, personality traits, and selected fictional universes.

I need a reusable scraper that collects character metadata from multiple permitted public sources and exports clean, structured data for my website.

Target universes may include:
- Marvel
- DC Comics
- Harry Potter
- Disney
- Anime
- Hollywood movies and TV series

Do not assume every source contains every field. Preserve missing values as null instead of inventing facts.

## 2. Technology Stack

Use:
- Python 3.11+
- Scrapy
- Pydantic for data validation
- JSON Lines and JSON export
- pytest for unit testing
- Pillow for optional image validation and processing

Keep the architecture modular so additional data sources can be added without rewriting the scraper.

## 4. Scraper Requirements

Implement the following:

### A. Modular spiders
- Create a separate spider or adapter for each supported source.
- Begin with one source that explicitly permits the intended collection.
- Avoid hard-coding website-specific selectors throughout the project.
- Handle pagination where permitted.
- Extract character names, descriptions, birth dates, image URLs, and source URLs when available.
- Respect each website's terms, robots.txt guidance, and applicable access restrictions.
- Do not bypass authentication, CAPTCHAs, paywalls, or anti-bot controls.

### B. Data validation
- Validate all records using Pydantic.
- Normalize whitespace and text encoding.
- Normalize universe names consistently.
- Reject malformed URLs.
- Preserve unknown values as null.
- Log invalid records instead of silently discarding them.

### C. Duplicate detection
- Generate stable character IDs.
- Detect duplicate records using source IDs, canonical URLs, aliases, and normalized names.
- Do not merge different versions of the same character automatically.
- Keep a distinction between comic, animated, and movie versions when the source supports it.

### D. Image handling
- Store image URLs separately from character metadata.
- Download images only when the source permits it and the intended use is licensed.
- Verify image content types and file sizes.
- Support configurable image dimensions and formats.
- Generate thumbnails only when image processing is enabled.
- Never assume that publicly accessible images are free for commercial use.
- Record licensing and attribution information when available.

### E. Zodiac assignment
- Calculate zodiac signs from verified birth dates only when the date represents the character's established birth date.
- Do not confuse fictional release dates or actor birth dates with character birth dates.
- If no reliable birth date exists, set zodiac_sign to null.
- Allow a separate configurable personality-based fictional matching label, clearly distinguished from an official or birth-date-derived zodiac sign.

## 5. Scalability and Performance

Implement:
- Configurable concurrency and download delays.
- Request timeouts and bounded retries.
- Per-domain rate limits.
- Incremental scraping.
- HTTP caching for development and permitted sources.
- Structured logging.
- Checkpoint-friendly exports.
- Separate metadata scraping from image downloading.
- Configurable limits for records and downloaded image sizes.

Do not implement distributed infrastructure unless there is a demonstrated need.
